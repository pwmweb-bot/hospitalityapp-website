What it does

The pass, on a screen.

  • Pass view — every open ticket, in the order it landed, with elapsed time.
  • Station filter — pin a screen to Grill / Larder / Pastry / Bar or any custom station.
  • Auto-routing — each product's station is set in the till back office; the KDS decides which screen sees what.
  • Item marks — item-by-item or whole-ticket, configurable per venue.
  • Notes and allergens come through from the till and mobile ordering, printed on the ticket in the format your chefs already read.
  • No hardware lock-in — any spare tablet, paired with a single-use code, boots straight into the display.
Why it matters

What the screen fixes that the printer never could.

Every kitchen has had the same three arguments for as long as there have been kitchens: where is that ticket, which table was that for, and did we fire that? A screen answers all three at a glance. The ticket is on the screen until it's cleared; the table number is printed at the top in whichever size the KO wanted; the fire mark is a colour, not a memory.

The station model is the other quiet win. Routing is a product setting, not a habit — a new item joins the correct station the day it goes on sale, and a menu change doesn't require re-training the pass.

How it joins to the rest

The KDS is downstream of the order.

Till / POS →

Products carry their station in the till; the KDS picks it up automatically.

Mobile ordering →

Server phones send tickets to the same KDS with the same routing. The kitchen doesn't care what took the order.

Reporting & insights →

Sales-vs-staffing and busy-periods analytics are built from ticket timestamps — the same data the pass is running on.
